# Blog comment section

Status: live
Owner: @wenxichen
Last updated: 2026-05-25

## Problem

The Eleventy blog at `wenxichen.github.io` has no way for readers to leave
feedback or ask questions on individual posts. Adding a comment system has to
work within a static-site setup and the existing GitHub Pages deploy pipeline
(`.github/workflows/deploy.yml`).

## Decision

Use [giscus](https://giscus.app), a comment widget backed by GitHub
Discussions.

Rationale:

- Static-site friendly: it's a single `<script>` tag, no server, no DB.
- Privacy-respecting: no ads, no third-party tracking, no cookies beyond what
  GitHub itself sets when authenticating commenters.
- Native to the GitHub-hosted workflow: comments live in this repo's
  Discussions tab; moderation, notifications, and editing all happen on
  github.com.
- Free and open source.
- Audience fit: readers of this AI/ML blog overwhelmingly already have GitHub
  accounts, so the GitHub-login-required trade-off is acceptable.

### Alternatives considered

| Option | Why not chosen |
| --- | --- |
| utterances (GitHub Issues) | Predecessor of giscus. Each post becomes a GitHub Issue, no threading, no reactions. Largely superseded. |
| Disqus | Free tier injects ads, tracks visitors, heavy JS. Misaligned with the simple, privacy-respecting feel of this blog. |
| Self-hosted (Isso, Remark42, Commento) | Most flexible but requires running a server. Overkill for a personal blog. |
| Email links / no comments | Lowest friction but loses public discussion value. |

## Design

### Data flow

```
reader -> giscus iframe (giscus.app)
       -> GitHub OAuth (giscus app)
       -> GitHub Discussions API
       -> repo Discussions tab
```

When a post page loads, the giscus iframe queries the Discussions search API
for a discussion whose title matches the page's `data-term`. If none exists,
the giscus bot creates one the first time someone comments.

### Bilingual handling

This blog supports inline EN/ZH translations on the same URL via
`translation_key` in front matter (see `_includes/layouts/post.njk`,
`assets/lang-toggle.js`). Both languages share one canonical permalink, so
they automatically share **one** discussion thread under `pathname` mapping.

We use `data-mapping="pathname"` (the giscus default and the value
generated by giscus.app for this repo). The include also supports
`specific` / `number` mappings: when configured that way it emits
`data-term` derived from `giscus.term` -> `translation_key` -> `page.fileSlug`.
The current setup does not need this — pathname is sufficient because both
languages render at the same URL.

### Theme handling

`data-theme="preferred_color_scheme"` makes the giscus iframe follow the
reader's OS dark-mode preference, which matches the site's existing
`@media (prefers-color-scheme: dark)` styling in `assets/main.css`. No
per-page theme messaging is needed today.

### Per-post opt-out

A post can disable comments by adding `comments: false` to its front matter.
The post layout gates the include with `{% if comments !== false %}`.

## File-level changes

| File | Change |
| --- | --- |
| `_data/site.json` | Add a `giscus` config object (`repo`, `repoId`, `category`, `categoryId`, `mapping`, `reactionsEnabled`, `theme`). |
| `_includes/comments.njk` | New include containing the giscus `<script>` tag, reading values from `site.giscus`. |
| `_includes/layouts/post.njk` | Render `comments.njk` at the bottom of `<article>`, gated by `comments !== false`. |
| `assets/main.css` | Add `.post-comments` block: top border, vertical spacing, heading style. |
| `README.md` | Document the optional `comments: false` front-matter flag. |

## Operational notes

### One-time prerequisites (manual, in browser)

1. In `wenxichen/wenxichen.github.io` repo settings, enable **Discussions**.
2. Install the [giscus GitHub App](https://github.com/apps/giscus) and grant
   it access to this repo.
3. On [giscus.app](https://giscus.app), enter the repo and choose:
   - Discussion category: the default `Announcements` category of type
     **Announcement** (only maintainers can start new threads; readers
     reply). A custom `Comments` category works equally well; this repo
     uses `Announcements` for simplicity.
   - Mapping: `pathname` (default; both EN and ZH versions of a bilingual
     post render at the same URL, so they share one discussion thread).
4. Copy the generated `data-repo-id` and `data-category-id` values into
   `_data/site.json`.

Until those IDs are filled in, the include uses placeholder values and the
widget will render an error in the browser; this is intentional and signals
that the prereqs step is still pending.

### Moderating

Moderation happens on github.com under the repo's Discussions tab: edit,
hide, delete, lock, or mark as answer like any other Discussion.
Notifications follow the repo's normal subscription settings.

### Per-post opt-out

```yaml
---
title: "Example"
date: 2026-05-25
comments: false
---
```

## Out of scope

- Email notifications on new comments (use GitHub repo notifications).
- Migrating existing comments (none exist).
- A custom giscus theme matched to the site's CSS variables.
- An in-page light/dark toggle that retheme the giscus iframe.
