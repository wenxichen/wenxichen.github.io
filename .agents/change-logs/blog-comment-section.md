# blog-comment-section change log

Running log of changes to the blog comment section feature. Newest entries on
top. Each entry uses an ISO date heading. Spec lives at
[.agents/specs/blog-comment-section.md](../specs/blog-comment-section.md).

## 2026-05-25 (later same day) — go-live

Maintainer completed the giscus.app prerequisites and supplied real values.
Wired them in and adjusted the implementation to match the actual giscus.app
configuration:

- `_data/site.json`: filled in real `repoId`
  (`MDEwOlJlcG9zaXRvcnkxMDM3MDAwODg=`) and `categoryId`
  (`DIC_kwDOBi5WeM4C92RO`).
- Switched `category` from the planned `Comments` to `Announcements` (the
  default GitHub Discussions Announcement category) — equivalent in
  behavior, simpler since no custom category needed.
- Switched `mapping` from `specific` to `pathname`. Bilingual posts already
  share one URL via the inline language toggle, so `pathname` gives them a
  single shared discussion thread without needing a `data-term`. This also
  matches the snippet generated by giscus.app.
- Switched `inputPosition` to `bottom` (matches giscus.app default).
- Updated `_includes/comments.njk` to only emit `data-term` when mapping is
  `specific` or `number`; with `pathname` the attribute is omitted.
- Spec status updated from `implementing` to `live`; spec sections on
  bilingual handling and prerequisites updated to describe pathname mapping
  and the `Announcements` category.
- README updated to reflect pathname mapping and the `Announcements`
  category.

Comments are now live on every post that does not opt out via
`comments: false`.

## 2026-05-25

Initial implementation: integrate giscus (GitHub Discussions-backed comments)
into the Eleventy blog.

- Added `giscus` config block to `_data/site.json` with placeholder
  `repoId` / `categoryId` values to be filled in once the maintainer
  finishes the giscus.app prerequisites.
- Created `_includes/comments.njk` containing the giscus `<script>` tag.
  Uses `data-mapping="specific"` with `data-term` derived from a post's
  `translation_key` (falling back to `page.fileSlug`) so EN/ZH versions of a
  bilingual post share one discussion thread.
- Wired the include into `_includes/layouts/post.njk` at the bottom of
  `<article>`, gated by `{% if comments !== false %}` so individual posts
  can opt out via `comments: false` in front matter.
- Added `.post-comments` styling in `assets/main.css` (top border, spacing,
  heading scale).
- Documented the `comments: false` opt-out in `README.md` under "Writing New
  Posts".
- Authored design spec at `.agents/specs/blog-comment-section.md`.
